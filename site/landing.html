the lab orchestrator

The lab assembles itself.

lezz is the orchestration layer for a working prototype lab. It installs the other tools and keeps them current, brings a whole cluster up with one command, and gives every caller a trust rung you can measure rather than assume.

companion app

Watch the lab, not a log file.

lezz.sea is a small macOS app for watching an adhd cluster: the lights it reports, and the MCP traffic it logs, live.

  • Lights. Green, red, yellow, dark — with the instance name and its 42i trust rung, refreshed on an interval you set.
  • Events. One row per request, response, and light update, filterable and searchable, with the raw JSONL line on the context menu.
  • Discovery. Reads the lezz cluster registry, probes the default adhd endpoint, and watches Bonjour for the isotope service.
  • Drop targets. Drop a .jsonl log to stream it, or a config naming a server to add its cluster.

Tools that stay current

lezz install adhd fetches a managed tool from its own release. lezz tools upgrade compares each binary's version with the latest release and reinstalls it when it is older, so nothing in the lab is left to rot.

One command, whole cluster

lezz demo brings up a self-contained cluster on stable ports. lezz auto starts a base cluster that is empty and awaiting peers, installing tools and reusing an existing registry.

Trust after connection

Whether a caller can still be trusted after it connects is a separate question from whether it could connect. Each caller carries a 42i distance that maps to a rung, and a rung limits what it may read. How surfaces and rungs work.

Start here

lezz install adhd     # fetch a managed tool from its own release
lezz demo             # start a self-contained cluster
lezz service list     # see what the lab is running
